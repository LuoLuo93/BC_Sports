# 新旧货分类设计文档

> 数仓 BI_DW(Oracle 19c),对应 SQL Server `dw.SP_SALES_Update_New_Old` 的 Oracle 实现。

## 一、背景

对销售货品按「品牌 / 季节 / 货品年份与销售年份的差距」做新旧货分类(下季新品、当季新品、专供新品、当季旧货、当季尾货、过季旧品、过季尾货、清货),用于销售分析。分类结果落到维度表,并按时间范围回填销售主表。

## 二、涉及的表

| 表 | 角色 | 说明 |
|---|---|---|
| `ODS_M_PRODUCT` | 物料维度(源) | 伯俊 M_PRODUCT + M_DIM 维度贴源,提供品牌/年份/季节/项目/滚动类型 |
| `DIM_TIME_MAIN` | 时间维度 | 提供 PRODUCT_SEASON(YYSS/YYAW)、PRODUCT_YEAR_SEASON_NO、DATE_INTACT |
| `DIM_PRODUCT_NEW_OLD` | **分类结果(全量刷新)** | 物料×销售季节的笛卡尔积 + new_old_type |
| `BC_SPORTS.BC_SPORTS_BI_GOODS_OLDNEW` | **自定义分类(覆盖,优先级最高)** | 与 BI_DW 同实例的 BC_SPORTS schema,按 货号+销售年季 覆盖分类(CATEGORY,现全为'滚动');**已取代 DIM_PRODUCT_NEW_OLD_CONFIG,后者不再维护/使用** |
| `ODS_SALES_MAIN.NEW_OLD_NAME_ADJUST` | **回填目标** | 销售明细的新旧货字段 |

### 关联关系
- `ODS_M_PRODUCT.NAME` = `ODS_SALES_MAIN.PRODUCT_CODE`(货号关联)
- `DIM_TIME_MAIN.PRODUCT_SEASON` = 货品/销售年份季节(如 `26SS`/`26AW`)
- `DIM_PRODUCT_NEW_OLD.MATERIAL_ID` = `ODS_M_PRODUCT.ID`

## 三、分类规则

核心变量:
- `PRODUCT_YEAR_SEASON_NO`(PYSN):货品年份季节序号
- `SALE_YEAR_SEASON_NO`(SLYSN):销售年份季节序号
- `SALE_YEAR - PRODUCT_YEAR`:销售年份 - 货品年份
- `PRODUCT_SEASON` / `SALE_SEASON`:SS/AW
- `MAT_TYPE_NAME`:滚动sku / 非滚动sku(**2026-08 起分类规则不再使用,仅作为维度字段保留**)
- `CARD_NAME`:品牌(LOWA、LEKI徒步、NORTHLAND 等有特殊逻辑)

分类(UPDATE 顺序,后者覆盖前者;即清货优先级最高):

| 顺序 | 类型 | 条件概要(**2026-08 起 MAT_TYPE_NAME 判断已全部移除**) |
|---|---|---|
| 1 | 下季新品 | 非LOWA/LEKI,季节序号差 ≤ -2(同季)或 ≤ -1(异季);或 LOWA/LEKI 销售年<货品年 |
| 2 | 当季新品 | 季节序号相等(非LOWA/LEKI);或 LOWA/LEKI 年份差 0~1 |
| 3 | 专供新品 | 非LOWA/LEKI,季节序号相等,ITEM=电商专供 |
| 4 | 当季旧货 | 非LOWA/LEKI,差=2;或 LOWA/LEKI 同季 年份差 2~3 |
| 5 | 当季尾货 | 非LOWA/LEKI,同季 差>2;或 LOWA/LEKI 同季 差≥4 |
| 6 | 过季旧品 | 非LOWA/LEKI,差=1;或 LOWA/LEKI 异季 年份差 2~3 |
| 7 | 过季尾货 | 非LOWA/LEKI,异季 差>1;或 LOWA/LEKI 异季 差≥4 |
| 8 | 清货 | NATURE URBAN/NORTHLAND/NORTHLAND.KIDS/HALTI,异季 差>3 或 同季 差>4 |
| 9 | **自定义覆盖(最高)** | `BC_SPORTS_BI_GOODS_OLDNEW` 按 货号(ARTICLE_NO)+销售年季(SEASON) 命中即覆盖(含已分类行),取 CATEGORY;原 CONFIG 表步骤已删除 |

> LOWA、LEKI徒步 用「销售年份-货品年份」判断;其他品牌用「季节序号差」判断。

## 四、存储过程 SP_UPDATE_NEW_OLD

**参数:** `P_START_TIME`, `P_END_TIME`(VARCHAR2,格式 `YYYY-MM-DD HH24:MI:SS`)— 回填 ODS_SALES_MAIN 的时间范围。

**步骤:**
1. `TRUNCATE DIM_PRODUCT_NEW_OLD` + INSERT 物料×销售季节笛卡尔积(new_old_type 初始 NULL)
2. 分步 UPDATE 设 new_old_type(8 类,忠于原 SP 顺序;**已移除全部 MAT_TYPE_NAME='非滚动sku' 判断**)
3. MERGE `BC_SPORTS.BC_SPORTS_BI_GOODS_OLDNEW` 自定义覆盖(货号+销售年季,命中即覆盖,优先级最高;过滤 DELETED=0 且 CATEGORY 非空;bi_dw 已获 GRANT SELECT;**原 DIM_PRODUCT_NEW_OLD_CONFIG 步骤已删除,该表不再维护**)
4. MERGE 回填 `ODS_SALES_MAIN.NEW_OLD_NAME_ADJUST`(按 BILL_TIME 范围,关联 物料+时间维度+分类结果)

**调用:**
```sql
EXEC SP_UPDATE_NEW_OLD('2026-07-28 00:00:00', '2026-08-05 23:59:59');
```

## 五、关键技术点

1. **物料维度源**:伯俊 `M_PRODUCT` 通过 `M_DIM1~32_ID` 关联 `M_DIM` 取维度(`M_DIMDEF.DIMFLAG` 标注:品牌=DIM1,年份=DIM2,季节=DIM3,货品类别=DIM4,系列=DIM6,子系列=DIM7,货品项目=DIM8,子项目=DIM9,款型=DIM10,性别=DIM12)。滚动类型由 DIM8 ATTRIBNAME 判断('滚动'→滚动sku,否则非滚动sku)。
2. **INSERT 用 EXECUTE IMMEDIATE**:绕过 PL/SQL 编译期 INSERT...SELECT 字符集推断(ORA-12704)。
3. **TO_NUMBER 防错**:`TO_NUMBER(x DEFAULT NULL ON CONVERSION ERROR)`(19c 内置),非数字年份返回 NULL 不中断。
4. **参数 VARCHAR2 + TO_DATE**:避免 Kettle 调用时 NLS_DATE_FORMAT 隐式转换报 ORA-01861。
5. **回填按 BILL_TIME 范围增量**:范围内才更新,范围外保持(增量设计)。

## 七、测试结果(2026-07-28 ~ 2026-08-05)

- DIM_PRODUCT_NEW_OLD 8 类全部分类(清货/下季新品/过季尾货/当季尾货/当季新品/当季旧货/过季旧品/专供新品)
- ODS_SALES_MAIN 范围内 **100% 回填**(39281/39281)
- 抽查验证:NORTHLAND 2024春夏(非滚动)在 2026 → 当季尾货,逻辑正确

## 八、变更记录 / 注意

1. **2026-08-14 移除 MAT_TYPE_NAME 判断**:8 条分类 UPDATE 中 `MAT_TYPE_NAME='非滚动sku'` 全部删除,滚动/非滚动 SKU 统一按季编号差/年份差规则分类;原本"滚动 SKU 不被分类(NULL)"的场景改由第 10 步兜底覆盖处理。
2. **2026-08-14 新增自定义覆盖并废弃 CONFIG 表**:分类 UPDATE 后 MERGE `BC_SPORTS.BC_SPORTS_BI_GOODS_OLDNEW`(BC_SPORTS schema,与 BI_DW 同实例 192.168.5.177:orcl)按 货号+销售年季 命中即覆盖,当前 CATEGORY 全为'滚动';原 `DIM_PRODUCT_NEW_OLD_CONFIG` 覆盖步骤已删除,该表不再维护。
3. 与 SQL Server 原版 `DW.dbo.SP_SALES_Update_New_Old`(192.168.5.152)已逐条比对:中文常量/品牌常量/数值边界/UPDATE 顺序均一致;**已知差异**——原版"下季新品"第一条因 AND/OR 优先级,其"异季差≤-1"分支对 LOWA/LEKI 也生效,Oracle 版被品牌过滤包裹,年差≥2 的极端组合分类会不同(业务上罕见,暂保持 Oracle 写法)。
4. 全量回填 ODS_SALES_MAIN 时,用覆盖全部 BILL_TIME 的范围参数跑一次。
5. 品牌 CARD_NAME 区分大小写(LOWA/NORTHLAND 大写,LEKI徒步 中文;' NORTHLAND.KIDS' 带前导空格,与原版一致)。
6. **部署含中文脚本必须 UTF-8 会话**:`NLS_LANG=AMERICAN_AMERICA.AL32UTF8`(库字符集 AL32UTF8),用 `deploy.sh` 部署即可,否则中文常量乱码。

## 九、已知问题: DIM_PRODUCT_NEW_OLD 笛卡尔积膨胀(待优化)

`DIM_PRODUCT_NEW_OLD` = 物料 × 销售季节 笛卡尔积,两边都增长,会膨胀。当前 ~133 万行(58163 物料 × 23 季节),其中销售数据只有 2026,约 98 万行(2017~2025 无销售的历史季节)是浪费。

**时间参数仅控制第④步回填范围,不影响 ①②③ 步的全量分类计算。**

优化方案(暂缓,记录待处理):
- **方案 A(短期,改 1 行 WHERE)**:bas_dtm 季节范围对齐销售数据,从 `BETWEEN 2018 AND 今年+2` 改为 `BETWEEN (SELECT MIN(销售年) FROM ODS_SALES_MAIN) AND 今天+2`,预计减 75%。
- **方案 B(长期,重构)**:DIM_PRODUCT_NEW_OLD 只存物料分类属性(每物料 1 行,不×季节),回填时 JOIN DIM_TIME_MAIN 动态算 new_old_type,彻底摆脱乘积膨胀。
